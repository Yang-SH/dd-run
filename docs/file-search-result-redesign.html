  • docs/icons-typography-plan.md §5.3「明确不采纳」首条即：「两行文件名——B5 刚决策单行 + 整行 hover tooltip；两行使行高动态化、与 40px D8 几何契约冲突，启动器场景收益低」。
  • app/mod.rs::base_height_for_workarea 用 单一 row_h 折算面板默认高度（rows × row_h + 92），row.rs:33 用同一 row_h 预留指针命中矩形，「一屏 9–12 行」也是按它推导的。逐行变高会让面板高度语义与命中矩形同时失准。
v2 因此改为行高完全不变、只用右列承载地址——既让地址常显，又零几何改动、零新增字段。
根因（新版代码复核）：协议层一直有完整路径——dd-ext/src/bin/search.rs:733 subtitle: Some(path.clone())。丢失发生在渲染层：16a3b07（B5）把副标题从行内移除、改由整行 hover tooltip 承载，而文件结果的地址是需要「一眼可见」的信息，不该藏在悬停里；此前的老布局（B5 之前）虽在行内，又有「剩余空间 ≥48px 才画、最多 240px」的门控，长文件名时整段丢弃。

C · 设计说明

1 · 设计决策

  • 行高不变：仍是 theme::ListMetrics::row_h（标准档 ROW_H = 40；紧凑 36 / 宽松 44）。不引入逐行高度——D8 几何契约与面板高度折算（rows × row_h + 92）保持成立。
  • 右列语义分派：文件结果 → 所在文件夹路径；其余结果 → 来源类别标签（「应用 / 网页 / 系统 / 命令」，B5 原样）。
  • 为什么可以替换类别标签：文件结果的类别来自 aggregator::category_label_for(ext_id)，而文件搜索扩展 com.ddrun.search 不在内置映射表中，恒回退为「命令」——对该结果零信息量；分组标题「文件」已由 section 表达。让位给地址是纯增益。
  • 右列只显示父目录（C:\a\b\f.txt → C:\a\b）：文件名已在标题，右列重复无意义；中段省略后「首段保盘符、尾段保最靠近文件的父目录」，定位信息最大化。
  • 中段省略优于尾省略：文件搜索场景下用户靠「盘符/根 + 深层父目录」定位，尾部 240px 截断会把最有用的深层目录切掉。
  • tooltip 兜底：文件结果的行 tooltip 恒给完整路径（含文件名），任何面板宽度下地址都不丢。
  • 零协议改动 / 零状态层改动：只用既有 PanelItem.subtitle(路径)、tags(["files"])、result_category、section、more_commands。未新增字段（v1 的 details 透传已撤销）。

3 · 实现落点（已落地）

  • crates/dd-gui/src/ui/row.rs 常量：FILE_PATH_W_FRACTION = 0.45、FILE_PATH_MIN_W = 120.0、CAT_LABEL_MAX_W = 90.0、TRAIL_GAP = 12.0。
  • is_file_item(item) = tags 含 "files" 且 subtitle 形如绝对路径（looks_like_path）。两个条件缺一不可：文件搜索扩展的入口项 files.search 与 files.search.query 同样带 "files" 标签，但副标题是说明文案（「输入关键词搜索本地文件」）而非路径，只看 tags 会误判。
  • file_location(path)：取父目录（C:\f.txt → C:\；UNC 保留 \\server\share；无分隔符原样返回）。
  • middle_ellipsis_chars(text, max_chars)：纯函数，保留首尾折叠 …（可单测）；middle_ellipsis(ui, text, font, max_w)：按平均字宽估算 + 实测收敛，保证不溢出。
  • draw_item_row：右列文本由 file_item 分派；宽度预算 = trail_w = measure(trail).min(可用宽 × 0.45)，标题宽 = 剩余 − trail_w − 12px。
  • 单行其余结果路径逐字未改（B5 逻辑保留，含 allocate_exact_size + child Ui 左对齐惯用法）。
