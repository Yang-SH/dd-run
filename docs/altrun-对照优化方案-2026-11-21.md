**动机**：ALTRun 的匹配字符高亮是默认体验（连续字符/首字母/拼音命中都高亮）。dd-run 结果列表无任何命中区间提示——尤其拼音命中（`jsq` → 计算器）时用户看不到「为什么命中」，是全结果可用性的最大单点提升。

**现状取证**：`crates/dd-gui/src/fuzzy.rs` 的 `FuzzyMatcher::score`/`field_score` 只取分值——nucleo `Pattern::score` 返回 `Option<u32>`，不取命中索引；渲染层（`crates/dd-gui/src/ui/` 下 row/panel）无任何 highlight/matched-range 符号。拼音 haystack = `pinyin_haystack`（`crates/dd-gui/src/state.rs`）生成的「全拼 + 空格 + 首字母」串，**无字符映射表**。nucleo-matcher 版本 0.3.1（Cargo.lock 实查），其 `Pattern::indices(haystack, matcher, &mut Vec<u32>) -> Option<u32>` 可取命中索引（docs.rs 实证；多原子时索引逐原子追加、不排序去重——需 `sort_unstable()` + `dedup()`）。

**设计**：

1. **评分热路径零变化**：排序阶段继续用 `Pattern::score`（hot_paths bench 基线不动）。
2. **高亮索引二遍算**：排序完成后仅对**当前可见行**（`recompute_visible` 产物）调用 `Pattern::indices`，结果存 `PanelState` 新增 `highlight_map: HashMap<String /* usage_key */, Vec<usize /* 命中字符索引 */>>`；查询变化/滚动换页重算，规模 = 单屏行数（≤ 30），不构成热路径回归面。命中字段取主命中字段（`field_score` 的 primary/secondary 判定已有）。
3. **拼音命中映射**：`pinyin_haystack` 旁新增伴生纯函数 `pinyin_haystack_with_spans(s) -> (String, Vec<u32>)`——span 表把 haystack 每个字符映射回 title 字符索引（全拼字符 → 源汉字；首字母段 → 同一源汉字；非汉字字符跳过、映射表对应段留哨兵）。`PanelItem` 是协议冻结结构**不加字段**：span 表作为宿主内存伴生数据，聚合构建时存 `PanelState` 新增 `pinyin_spans: HashMap<String, Vec<u32>>`（键 = usage_key）。拼音字段命中时，命中索引经 span 表映射回 title 字符得到高亮区间。`custom_command_items` 等宿主虚拟条目同步填充。
4. **渲染**：`ui/row.rs` 标题改富文本段（egui `LayoutJob`/分段 RichText）——命中字符用强调色（`theme/palette.rs` 的 `Palette::accent`，随 ColorizationMode 三档；`ui/row.rs` 已消费 accent 绘制选中竖条，取色路径现成）+ 保持常规字重，其余常规。空查询 / 无命中不高亮。行高、布局、金图基线：**命中态是新增态，金图新增 1 张命中样例图**（快照 job 既有护栏），非命中态布局逐位不变。
5. IME/键盘行为不变；高亮映射仅是渲染层信息，不参与排序。

**可行性依据**：nucleo-matcher 已在依赖树（零新增）；span 生成是纯函数可全单测；富文本着色是 egui 既有能力（着色三档已验收）；`usage_key` 键函数已在 `usage.rs`。

### 4.3 N8 · calc 增强：函数 + 进制 + 日期运算

> 对照初版清单 A3 ｜ P2 ｜ 无依赖（chrono 已在 dd-ext 直接依赖树） ｜ 约 300 行 + 单测

**动机**：ALTRun 计算器支持进制转换（`255 in hex`）、日期运算（`today + 30 days`）；dd-run `calc.rs` 为手写递归下降（四则/幂/括号/一元正负/小数与科学计数法/pi/e），无函数、无进制、无日期。

**现状取证**：`crates/dd-ext/src/builtins/calc.rs`——`eval_expr` 入口 + `parse_expr/parse_term/parse_unary/parse_power/parse_atom`；`parse_atom` 的 ident 分支已处理 `pi`/`e` 常量；`chrono = "0.4"` 已是 dd-ext 直接依赖（Cargo.toml 实查，文件 mtime 用途）——日期运算可零新增使用。结果形态 = `ShowToast` + `host/set_clipboard`，兜底模板 `= {query}`。

**设计**：

1. **函数**：`parse_atom` 的 ident 分支扩展——ident 后跟 `(` 时按函数解析；`FUNCS` 表（arity 内建校验）：`sqrt/abs/exp/ln/log(底 10)/round/floor/ceil/sin/cos/tan/asin/acos/atan`（单参）+ `min/max/pow/mod`（双参）。未知函数/arity 不符 → `EvalError::UnknownFunction`/`BadArity`（错误文案 zh/en 进内联 tr）。定义域守卫：`sqrt` 负数、`ln/log` 非正数、`asin/acos` 域外 → `EvalError::Domain`。
2. **进制字面量**：数字词法层扩展 `0x[0-9a-fA-F]+` / `0b[01]+` / `0o[0-7]+`。
3. **进制转换**：`eval_expr` 入口预处理 `X in hex|bin|oct|dec`（先按常规语法求值 X，须为**非负整数**——含小数/负数回 `EvalError::NotInteger`）；输出带前缀串（`0x`/`0b`/`0o`；dec 裸串）。
4. **日期运算**：保留字 `today` / `now`；`today ± N day|days|week|weeks`（先于常规解析分支匹配，避免 `today` 进 ident 报错）；`now` 输出本地时间 `HH:MM`，`today ±` 输出 ISO 8601 日期 + 星期几（zh/en 文案）。日期算术用 chrono（`Local` + `Days`/周换算），civil 历法交给库（dd-ext 既有注释同口径：手搓 civil→days 易错）。
5. 结果展示/剪贴板/兜底模板行为不变。

**可行性依据**：递归下降解析器已可扩展（ident/number 分支既有）；chrono 在树零新增；错误枚举与 i18n 机制既有。

**冲突检查**：`in` 关键词与既有语法零冲突（`X in Y` 现为非法表达式，今天没有用户语法占用）；`today` 保留字与普通文本查询无冲突（calc 兜底仅在表达式可解析时接管）；协议零改动。

**验收草案**：
- [x] 单测：函数表 arity/未知函数/域错误；进制字面量与转换边界（`255 in hex` = `0xff`、`0xff in dec` = `255`、`0b101 in oct`；负数/小数拒绝）；`today + 30 days` / `today - 2 weeks` / `now` 格式；`2 2` MissingOperator 回归不破。
- [x] 真机：上述五类查询面板实查 + toast + 剪贴板。

**本项边界**：单位换算、汇率（§3.1）；month/year 日历运算（历法歧义，仅 day/week）；复数/虚数。

**设计**：缓存容器改 `OnceLock<RwLock<AppCacheInner>>`，`AppCacheInner = { apps: Vec<App>, enumerated_at: Instant }`。重枚举门控 = **面板唤起时**（宿主唤起钩子透传一次检查）且距上次枚举 ≥ 30 秒 → **全量重枚举一次完成**（AppsFolder COM + 开始菜单 .lnk 两根）。**刻意不做「.lnk 根签名变化才重枚举」的窄门**：UWP/打包应用新装不产生开始菜单 .lnk，纯 `AppsFolder` 变化会被签名门漏掉——与「免重启」目标矛盾；枚举成本由验收计时腿约束（目标 ≤ 50 ms，实测超阈则把「签名门」作为后续优化另立，且签名须同时盖 AppsFolder 与 .lnk 两源）。负缓存语义保留（panic → 空表 + 下次门控窗口重试）。条目 id 仍为枚举下标：重枚举致 id 漂移进而 usage 对位漂移是**既有已知口径**（安装/卸载今天也一样），本项不扩大该语义——id 稳定化（exe 路径派生）记为后续可选项，不随本项做。

**可行性依据**：OnceLock→RwLock 容器替换纯局部；签名函数纯可测；N2 注入链零改动。

**冲突检查**：内存纪律（M1–M4 口径）——枚举频率受 30s + 签名门控双闸，稳态零重付；N2 输出层过滤不变；虚拟化/性能 bench 无涉（apps 枚举不在 hot_paths 组）。

### 5.3 O17 · 更新下载 + SHA256 校验闭环

> P2 ｜ 约 250 行 + 单测 ｜ 边界：**不做自替换**（update_check.rs 既有决策「便携版静默替换 exe 风险大于收益」）

**动机**：ALTRun 自动更新带 SHA256 校验；dd-run 更新面止步于「检查」（`update_check.rs` 明示不自动安装），用户须自行去 Release 页比对校验。

**现状取证**：`update_check.rs`（系统 curl + GitHub API + 版本比较，`UpdateStatus::Available` 态）；release.yml 已产 `SHA256SUMS.txt`（全资产覆盖，`sha256sum -c` 可验）；数据目录 `cache/` 既有。

**设计**：

1. `Available` 态设置页出现「下载新版」按钮 → 系统 curl 下载 zip 到 `cache/updates/dd-run-<ver>.zip`（进度 toast，无进度条 UI——curl 静默 + 完成态提示）；同步拉取 `SHA256SUMS.txt` 并按文件名行比对校验。
2. 校验通过 → 打开所在目录 + toast 指引「解压覆盖即完成更新」（**不做自替换**——边界承既有决策口径）；校验失败 → 删除残留 + 失败 toast。
3. 零 HTTP crate（curl 既有取径）；`check_updates` 默认关不变；下载失败清理半截文件。

**冲突检查**：不做自动安装决策边界内（下载+校验+指引 ≠ 静默替换）；网络面与 update_check 同级扩展（同一信任面，隐私记档随批次回写）；SHA256SUMS 依赖 release 链既有产物（无新链路）。

**验收草案**：- [x] 单测：SHA256SUMS 解析/匹配/失败清理；- [x] 真机：构造低版本号 → 检测 → 下载 → 校验过；篡改 zip → 校验失败 + 清理（2026-11-24 A21，证据见 walkthrough §7.2 续跑记录 4）。

**落地注记（2026-11-22，波次二收口批 A-1）**：设计如上兑现——① **纯逻辑**（`update_check.rs`）：`UpdateStatus` 增 `Downloading` / `Downloaded { path }` / `VerifyFailed(String)` 三变体（GUI 内部枚举，零协议面）；SHA-256 纯函数实现（决策点按实施计划默认定案：零新增依赖，NIST 向量 ×4 单测锁定——空串 / "abc" / 56 字节跨块 / 百万 a）；`parse_sums`（sha256sum 两空格 / 二进制 ` *` / CRLF / 哈希大小写容错）+ `verify_sums` / `verify_zip_bytes`；资产直链 `releases/latest/download/{asset}`，zip 资产名**实测** `dd-run-<ver>-portable.zip`（portable_zip.ps1 / release.yml——实施计划初稿 `dd-run-<ver>.zip` 口径按发行链实测修正）。② **应用侧**（`app/update_check.rs`）：`start_update_download`（在途守卫——检查与下载共用 `update_rx` 单槽通道顺序复用；zip 300 s / SUMS 30 s 双超时；失败逐路径清理半截文件）；`poll_update_check` 三分支扩展（`Downloading` 不清通道；`Downloaded` → `ToastKind::Success` 启用（toast_state.rs 预留位）+ `reveal_in_folder` 定位 zip；`VerifyFailed` → Error toast）；view 增 `update_available` / `update_downloading` 两字段。③ **UI**（关于卡）：Available 态第二行「下载新版」（下载在途改显进行中文案，不渲染按钮防重复）。④ **边界兑现**：不做自替换；`check_updates` 默认关不变；lock 零新增；i18n +5 键（键表 198 → 203）。真机状态见本节验收复选框与清单 §5：低版本构造 → 检测 → 下载 → 校验过 → Explorer 定位；篡改 zip → 失败 + 清理。

### C.2 走查抓出的缺陷与修复（当场修复 + 单测 + 复验）

1. **N10 直达条目运行时惰性（波次一缺陷，真机抓出）**：注入挂在 `rebuild_root_from_arrived`（仅在启动/配置脏时发生，`restart_aggregation` 门控），其读取的查询恒为空 → **URL/路径直达条目实践中永不出现**（单测只测纯函数构造故全绿）。修复：`PanelState::set_direct_item`（state.rs）+ 根页输入路径逐键维护（panel.rs）；rebuild 注入保留为聚合时刻兜底（前缀去重幂等）。**连带修复首版引入的索引越界 panic**：Esc 清空路径 `set_query("")` 后下一帧 `set_direct_item(None)` 使 items 减一、同查询早退不重算 → `visible` 过期索引 → `filtered()` 越界（真机 panic 实录，glow destroy 警告佐证）——`set_direct_item` 改为**自足重算**（同 id+内容重复注入零操作，稳态帧零重付）。回归单测 ×2（`n10_set_direct_item_maintains_query_shaped_entry` / `n10_set_direct_item_clear_with_unchanged_query_no_stale_index`）。
2. **N14 Ctrl+Enter Reveal 类别门控失配**：原按「类别 ∈ {应用,文件}」门控，但文件搜索页行 `result_category` 缺省（sidecar 只设 section）、N10 直达行类别「直达」→ 两者误落 Copy(标题)，与设计「应用/文件/路径直达行 = 打开所在位置」不符。修复：`ctrl_enter_kind` 改**形状门控**（副标题 path_like → Reveal；url_like → Copy(链接)；否则 Copy(标题)），签名去 category 参数，测试扩直达/缺省类别回归断言。
3. **N19 SaveAsCommand 真实行型不可达**：直达行菜单无转存项（转存仅挂网页/文件类别）；文件臂 `Some("文件")` 因类别缺省同样不可达（与 ② 同族）。修复：直达行菜单补挂「存为自定义命令」（URL/Path 按 target 形态，title 建议=target）；文件动作改类别缺省+路径形态兜底门控（ctx_menu.rs）。
