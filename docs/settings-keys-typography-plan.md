## 0. 结论先行

针对 2026-09-24 真机截图反馈的「设置 → 常规 → 按键与交互」卡排版问题与全设置页控件字体偏大问题，本方案给出两组纯视觉改动（**零行为变更、零协议改动、零设置项变更**）：

| # | 问题（真机截图证实） | 根因 | 措施 | 优先级 |
|---|---|---|---|---|
| K1 | 按键与交互卡行距局促、卡头与行区间距偏小、行名-描述间距与其他卡不一致 | 行块间 `add_space(8)`、卡头后 `add_space(8)`；自启/语言卡行名-描述间有 `add_space(2)` 而本卡没有 | 行块高 36→40、行区间距 8→12、卡头-行区间距 8→12、行名-描述统一 `add_space(2)`，并**全设置页同形态行统一** | P1 |
| K2 | 下拉框/按钮等控件文字与行名同级（14pt），控件盒（32 高）在 36 高的行块里占比 89%，视觉笨重、比例失调 | v4.9/D34「整体字号放大」把**控件**与**正文**一并放大到 14，未区分层级 | 自绘控件文字 14→12（ramp base200）、控件盒高 32→28（Fluent compact 比例），全设置页统一 | P1 |
| K3 | 下拉框宽度三卡不一（200/180/260），英文文案溢出盒外无兜底 | 宽度为逐卡硬编码常量，无内容自适应规则 | 宽度规则统一为 `clamp(内容宽+40, 180, 260)` 纯函数 + 单测 | P2 |

**决策编号**：D41（设计稿决策清单延续，v4.19 入稿）；**部分修订 D34 ③**（v4.9「整体字号放大」中控件部分的回调——正文/行名字号不动，仅控件回调一档，见 §3.5）。

**改动面**：仅 `settings_view.rs`（约 12 处字面量收口为常量）+ 设计稿修订；不动 `theme.rs` 色板/密度、不动 `settings.rs`、不动 `keys.rs` 行为链路、不动 D8 列表行几何契约。

## 2. 根因分析

1. **层级缺档**：设计稿 05.1 字号 ramp 为 base100(10)/base200(12)/base300(14)/base400(16)/base500(20)。当前设置页正文层（行名 14 semibold）与控件层（下拉/按钮/输入 14 regular）**同落 base300**，控件失去「次级」视觉定位。
2. **v4.9/D34 的历史语境已变**：D34 放大字号的动机是「控件整体偏小、按钮长期漂移为 26px/12px **文字链接**」——当时控件尚未形态化。如今控件已是「1px 描边 + card 底 + 圆角」的正规 Fluent 控件，盒体自身已提供视觉重量，14pt 文字叠 32px 盒在本就紧凑的 36px 行块中过载。**本稿不翻案 D34 的正文放大（行名 14 / 描述 12 保持），仅回调控件部分**，并在设计稿记 D41。
3. **设计稿依据**：设计稿中语言卡 ComboBox 的演示形态即 `font-size: var(--font-caption)`（=12px）+ 4/10 padding 的 chip——「控件文字 = caption 档」在稿内有先例，非新造规格。
4. **行块 36 偏小**：列表行标准高 40（D8/F2），设置行块 36 与系统其余部分不一致，也是控件占比失衡的放大器。

## 3. 方案详设

### 3.1 控件排印统一（K2）——新常量组收口

`settings_view.rs` 顶部新增常量组（收口散落字面量，供断言单测锚定）：

```rust
// 设置页自绘控件排印（D41：Fluent compact 档，文字 = ramp base200）
pub(crate) const CONTROL_H: f32 = 28.0;          // 下拉框/标准按钮/输入框盒高（原 32）
pub(crate) const CONTROL_FONT_PT: f32 = 12.0;    // 控件文字（原 14；ramp base200）
const POPUP_ITEM_H: f32 = 24.0;                  // 下拉 popup 选项行高（原 28）
```

| 落点 | 改法 |
|---|---|
| `draw_fluent_dropdown` 约 :2507-2508 | `h: 32→CONTROL_H`、`font: 14→CONTROL_FONT_PT`；popup 选项行 :2578 `28→POPUP_ITEM_H`、:2592 文字 `font.clone()`（自动随 12）；▼ 箭头 10pt 不动 |
| `fluent_button` 约 :2399 | `fluent_button_sized(ui, text, p, 32.0, 14.0, 12.0)` → `(…, CONTROL_H, CONTROL_FONT_PT, 12.0)` |
| `fluent_button_small` 约 :2404 | **不动**（24/12/8 已 = 目标档，与统一后口径一致） |
| URL 输入框 约 :1632, :1663 | 高 `32→CONTROL_H`、font `14→CONTROL_FONT_PT` |
| 预测量调用点 :941-942, :1628 | `FontId::proportional(14.0)` → `CONTROL_FONT_PT`（行宽预留随真实字宽） |
| popup `gap(4.0)`、圆角 4/2、描边 1px border-strong、三态 hover 链 | **不动** |

### 3.2 「按键与交互」卡排版（K1）——并全设置页同形态行统一

目标布局（单卡四行 + 卡头，不拆卡）：

```text
┌─ 卡（padding 12，圆角 8，1px border）─────────────────────┐
│ [E765 16px] 按键与交互            ← 卡名 14/600（不动）    │
│             Esc、退格、单击与动效…  ← 描述 12（不动）       │
│                              ↕ 12（原 8）                  │
│ Esc 键行为                       [ 下拉 28 高 × 自适应宽 ]  │
│ 选择 Esc 键的行为   ←行名/描述间 +2                      │
│                              ↕ 12（原 8）                  │
│ 退格键返回                              [ 开关 40×20 ]     │
│ 搜索框为空时按 Backspace 返回上一级                        │
│                              ↕ 12                          │
│ 单击激活                                [ 开关 40×20 ]     │
│                              ↕ 12                          │
│ 界面动效                                [ 开关 40×20 ]     │
└──────────────────────────────────────────────────────────┘
```

| 规则 | 目标值 | 落点（约） |
|---|---|---|
| 行块高 | 36 → **40**（行名 14/20 + 描述 12/16 + 名-描间 2 = 38，留 2px 余量）。机制按卡而异：按键卡 4 行与语言卡为 `allocate_ui(…, 36)`（:1273, :1303, :1329, :1355, :1114）→ 改高 40；自启卡 :1057 与搜索行为卡 :1189 为 `set_min_height(36.0)` → 改 40 | 同上各落点 |
| 行区间距 | 8 → **12** | :1269, :1299, :1325, :1351 |
| 卡头→行 1 间距 | 8 → **12** | :1269（与行区间距同值，分组节奏一致） |
| 行名→描述 | 统一补 `add_space(2.0)`（多数卡既有口径，见 §1.2） | :1275-1288 等四处；顺带修正 :1195 的错注释「材质卡口径」→ 实值随统一 |
| 左块宽公式 | 统一 `(available − 右控件宽 − 16).max(160)`；行 2-4 右控件宽 = 开关 40（写法归一，消除 `available − 16` 特例） | :1270, :1300, :1326, :1352 |
| 右列对齐 | 右控件统一 `right_to_left(Align::Center)` 垂直居中（现状已是，写入规格防漂移） | 不改代码 |
| 卡头图标 | 16px 格 + glyph 16pt + 1px 光学下移、与文字组间距 12 | 不改代码（与自启/语言卡一致） |
| 分组 | **不拆卡**：四项同属「交互行为」域（对齐 CmdPal 设置页「行为」平铺模式）；行距 12 + 卡头分层已提供组内节奏 | — |

### 3.3 下拉框宽度自适应（K3）

新增纯函数（放 `settings_view.rs`，配单测）：

```rust
/// 下拉宽度 = clamp(最长选项宽 + 左右 pad 24 + 箭头区 16, 180, 260)。
/// zh 常态落 180（与语言卡 D38 规格一致）；长英文选项撑到上限 260 封顶。
fn dropdown_width(ui: &egui::Ui, labels: &[&str]) -> f32
```

| 卡 | 现宽 | 改后 |
|---|---|---|
| Esc 键行为 | 200 | zh ≈ 180（「返回上一级（默认）」≈126 + 40）；en「Clear the search first, then go back」撑至 ≤260，消除现状溢出盒外 |
| 语言 | 180 | 规则不变（内容短，落 180） |
| 搜索引擎预设 | 260 | 规则不变（长 URL 预设落上限） |

实现注：超上限仍溢出的极端文案不做字符截断（三卡现有选项集实测均 ≤260，`EscBehavior::ALL`/`Lang`/预设引擎均短文案）；上限即兜底。

## 7. 不做项与理由

| 项 | 理由 |
|---|---|
| 拆分「按键与交互」为多卡 | 四项同域，CmdPal 同类设置平铺一卡；拆卡反增纵向长度（§3.2） |
| 控件盒维持 32 高、仅降字号 | 12pt 文字 + 32px 盒比例失衡（空旷），「笨重」观感改善有限；28+12 为 Fluent compact 成对比例 |
| 新增 13pt 中间档字号 | 破坏 ramp 4px 精神（10/12/14/16/20），且 egui 渲染 13 与 12 观感差异不可辨 |
| 行块接入密度三档联动 | 设置页非结果列表，ListMetrics 不适用；避免 D8 契约面扩大 |
| dropdown 极端长文案字符截断（…） | 现有选项集实测均在上限内；上限 clamp 已兜底，截断逻辑属过度设计 |
| 全仓 89 处 `size()` 大扫除 | 同 icons-typography-plan F1 结论：设置页外各有机理与锚点，收益低风险高 |
