本工作流四项均无外部条件依赖，逐项验收判据以清单对应小节为准。

| 项 | 内容 | 验收 |
|---|---|---|
| cargo-deny 许可证门禁 | ✅ **已完成（2026-10-30）**——`deny.toml` 实测最小集落仓库根目录（较清单 §2.1 原建议五族另需 BSL-1.0 / MPL-2.0 / OFL-1.1 / Ubuntu-font-1.0 / Zlib，逐条理由见文件内注记）+ ci.yml audit job 步骤落地（install-action 追加 cargo-deny——其支持清单内含该工具经 TOOLS.md 实证；`cargo deny check licenses bans` 直接阻塞）。**CI 首跑腿待验**：push 后由改门禁文件的 PR 自身实证；deny.toml 提交时须与 ci.yml 同批入库 | 三平台 CI 全绿并阻塞（清单 §2.1 已销项，CI 腿待 push 实证） |
| 协议解码边界 fuzz | ✅ **初始化完成 + 七夜时钟已起算（2026-10-31 绿灯首跑 run 41150767528，decoder/envelope 双 target 步骤级 success）**——`fuzz/` 独立 crate（隔离 workspace，主 lock 零新增）+ 双 target（decoder / envelope，断言不 panic + 契约不变式）+ 语料 20 枚入库（envelope 侧 `ParseError`/`InvalidReason` 各分支一枚）+ `fuzz.yml` 夜间观察 job（每晚 21:00 UTC + 手动 dispatch；`RUSTUP_TOOLCHAIN=nightly`；crash 输入 base64 进日志；**run 显式 `--target x86_64-unknown-linux-gnu`**——新版 cargo-fuzz musl 默认与 nightly minimal/ASan 不兼容，R1 实证修正）。本机 windows 不可跑（msvc ASan/sancov 链接摩擦，计划预案内），运行平台 = CI ubuntu；观察结果记 implementation.md | 连续 7 夜 schedule 零 crash + Decoder ≥ 10⁷ 次执行无 panic（清单 §2.2 销项后随 S4 转阻塞） |

## 7. 维护纪律与冲突核查
