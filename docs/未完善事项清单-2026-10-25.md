## 2. 一、代码级待办（可直接开工，无需外部条件）

### 2.1 cargo-deny 许可证门禁（改进分析 P2-5.6，P2 唯一未落地项）

- **现状**：CI 只有 `cargo audit`（漏洞）+ `cargo machete`（死依赖）；全仓声称 MIT，但三方依赖的许可证从未被机器校验。改进分析收口轮将其记档遗留（口径：cargo-deny 工具链当时不可本地验证），本清单承接为正式开放项。
- **建议**：加 `deny.toml`（允许 MIT / Apache-2.0 / BSD / ISC / Unicode-3.0，其余逐条审批），`cargo deny check licenses bans` 进 CI 阻塞门禁；许可证清单落入 docs。
- **验收**：`cargo deny check` 三平台 CI 全绿并阻塞。

### 2.2 协议解码边界 fuzz（改进分析 §4.4）

- **现状**：`crates/dd-protocol/src/framing.rs` 的 `Decoder` 直接消费不受信第三方扩展的 stdout（单帧上限 1 MiB），仓库无 `fuzz/` 目录、无 `cargo-fuzz` 配置。此项属改进分析 **P1 九项之一（§4.4）**，是 P1 唯一未闭环项；A–D 四批路线未纳入，收口轮记档遗留（口径：cargo-fuzz 工具链当时不可本地验证），本清单承接为正式开放项。
- **建议**：`cargo fuzz init` + 两个 target：`decoder`（任意 bytes → 只允许 Ok / Vec\<Frame\> / Err 三态，永不 panic）、`envelope`（任意帧 → 解析无 panic）。每天夜间跑 10 分钟，语料入库。
- **验收**：连续 7 天夜间 fuzz 零 crash；`Decoder` 在 ≥ 10⁷ 次执行后无 panic（OOM 与 `TooLarge` 路径除外）。

### 2.3 内置扩展跨平台扫描 TODO ×4

- **现状**：四处在位注释明确挂账，均等「对应平台轮」：
  - `crates/dd-ext/src/builtins/bookmarks.rs` 约 :416——浏览器书签路径只覆盖 Windows / Linux Chrome 目录，macOS 未扫；
  - `crates/dd-ext/src/builtins/apps.rs` 约 :2021——macOS 扫 /Applications、Linux 读 .desktop + PATH 未实现；
  - `crates/dd-ext/src/builtins/system.rs` 约 :314——macOS（pmset/osascript）与 Linux（systemctl）命令表未实现；
  - `crates/dd-ext/src/builtins/shell.rs` 约 :736——macOS / Linux 的 $SHELL 终端打开与执行未实现。
- **说明**：属 O6 跨平台路线的一部分，与「O6 ④ 非 Windows 真机腿」（§5.1）同轮处理较合算。

### 2.4 列表虚拟化判定腿（改进分析 §5「先测再决定」其一）

- **现状**：P2-4.5 已落地 criterion 基准（dd-gui `hot_paths` 3 组 + dd-protocol `decoder` 1 组）+ CI 趋势回归，但原判据「`ui/panel.rs` 逐行绘制若超过 8 ms/帧再上 `show_rows` 虚拟化」的**判定数据未跑数/未记档**——当前规模（400 应用 + 30 文件上限）大概率不是瓶颈，但不测不定案。
- **验收**：bench 结果记档；≤ 8 ms/帧则正式关闭（虚拟化永不立项），> 8 ms 才立项。
