## 2. 一、代码级待办（可直接开工，无需外部条件）

### 2.1 ~~cargo-deny 许可证门禁~~ ✅ 已销项（2026-10-30，CI 步骤落地）

- **现状**：CI 只有 `cargo audit`（漏洞）+ `cargo machete`（死依赖）；全仓声称 MIT，但三方依赖的许可证从未被机器校验。改进分析收口轮将其记档遗留（口径：cargo-deny 工具链当时不可本地验证），本清单承接为正式开放项。
- **建议**：加 `deny.toml`（允许 MIT / Apache-2.0 / BSD / ISC / Unicode-3.0，其余逐条审批），`cargo deny check licenses bans` 进 CI 阻塞门禁；许可证清单落入 docs。
- **实测注记（2026-10-28）**：上述建议五族允许清单**不足**——本机 cargo-deny 0.20.2 实测另有依赖被拒：clipboard-win / error-code（BSL-1.0）、nucleo / nucleo-matcher（MPL-2.0）、epaint_default_fonts（OFL-1.1 AND Ubuntu-font-1.0 内嵌字体）、Zlib 族 2 个依赖；**deny.toml 已按实测最小集落仓库根目录并全绿**（`cargo deny check licenses bans` = licenses ok / bans ok，逐条审批理由见文件内注记；剩余工作只有 CI 步骤，见 [实施计划-2026-10-28.md](./实施计划-2026-10-28.md) §2.3）。
- **验收**：`cargo deny check` 三平台 CI 全绿并阻塞。
- **销项（2026-10-30）**：ci.yml audit job 落地——install-action tool 清单追加 `cargo-deny`（**其支持清单内含该工具，2026-10-30 对 TOOLS.md 实证**，计划撰写时的「manifests 未核验」不确定性与回退方案 b 就此消除）+ job 末新增 `cargo deny check licenses bans` **直接阻塞**（无 continue-on-error）；job 名改「audit + deny + machete」。本机 2026-10-28 / 10-30 两轮实测 `licenses ok / bans ok`；清单 §8 优先级表已同步 strike。lock 零新增（deny.toml 为配置文件）。**CI 首跑腿待验**：改门禁文件的工作副本 push 后由其自身 PR 实证；**deny.toml 当前未跟踪，提交时须与 ci.yml 同批入库**，否则 CI 的 deny 检查因缺配置必红。

### 2.2 协议解码边界 fuzz（改进分析 §4.4）

- **现状**：`crates/dd-protocol/src/framing.rs` 的 `Decoder` 直接消费不受信第三方扩展的 stdout（单帧上限 1 MiB），仓库无 `fuzz/` 目录、无 `cargo-fuzz` 配置。此项属改进分析 **P1 九项之一（§4.4）**，是 P1 唯一未闭环项；A–D 四批路线未纳入，收口轮记档遗留（口径：cargo-fuzz 工具链当时不可本地验证），本清单承接为正式开放项。
- **建议**：`cargo fuzz init` + 两个 target：`decoder`（任意 bytes → 只允许 Ok / Vec\<Frame\> / Err 三态，永不 panic）、`envelope`（任意帧 → 解析无 panic）。每天夜间跑 10 分钟，语料入库。
- **验收**：连续 7 天夜间 fuzz 零 crash；`Decoder` 在 ≥ 10⁷ 次执行后无 panic（OOM 与 `TooLarge` 路径除外）。
- **初始化落地（2026-10-30，七夜验收时钟待 push 后起跑）**：`fuzz/` 独立 crate（隔离 `[workspace]`，主 Cargo.lock 零新增）+ 双 target（`decoder` 含两条契约不变式断言：`Message` ≤ 上限 / `TooLarge.size > max`；`envelope` 连带走 `to_error_response` 错误响应构造面）+ 语料种子 **20 枚**入库（envelope 侧 `ParseError` 与 `InvalidReason` 各分支一枚；decoder 侧除刻意不放的 1 MiB 超限路外全分支；JSON 语法机检 18 过 / 1 刻意失败——即 `-32700` 种子，另 2 枚为裸换行与二进制截断 UTF-8 不属 JSON 机检面）+ `.github/workflows/fuzz.yml` 夜间观察 job（schedule 每晚 21:00 UTC + workflow_dispatch 手动首跑；`RUSTUP_TOOLCHAIN=nightly` 覆盖工具链钉扎；crash 输入 base64 进日志替代 upload-artifact——仓库无该 action SHA pin）。**本机记档**：Windows 下 cargo-fuzz 运行不可行（msvc 链接缺 ASan 运行库 + sancov 符号，计划预案内情形），本地验证降级为 stable `cargo check`（双 target 编译过）+ 语料机检；运行平台 = CI ubuntu（nightly + 默认 ASan）。**七夜零 crash 后本节销项**，观察结果记 implementation.md。
