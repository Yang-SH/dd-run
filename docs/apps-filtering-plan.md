# Apps 扩展垃圾项过滤（应用列表优化）

> 状态：设计稿 v1.2（2026-09-12 立项 v1.0，经用户确认后实施；同日真机核验两轮修订——v1.1 补 §3.B AppsFolder 作用范围；v1.2 修 §3.C 去重键含参数 + 检查顺序、§3.A 撤 `_update` 后缀规则）
> 范围：**仅 `crates/dd-ext/src/builtins/apps.rs` 的开始菜单 `.lnk` / `.url` 兜底层**；AppsFolder 枚举（AUMID 路径）**完全不动**。
> 协议：**v1.0 零改动**（`dd-protocol` / `dd-ext::serve_line` / 清单 / 桩缓存机制均不动）。
> 参考基准：PowerToys Run **v0.101.2362.0**（本仓核验基准，`cmdpal-platform-agnostic-design.md` §11）、Flow Launcher dev 分支、ueli main 分支（源码已逐文件核实，见 §2）。

---

## 1. 动机与问题定位

用户反馈：应用列表混入**应用安装过程产生的、用户不会直接使用的 exe**（卸载器、更新器、崩溃报告器、维护工具等）。

现状过滤（`apps.rs::app_list()`，apps.rs:284）只有三条：

1. **AppsFolder 枚举**：parsing name 无路径分隔符 + 排除 `Microsoft.AutoGenerated.*`——AUMID 项基本是真实应用，垃圾残留少；
2. **开始菜单 `.lnk` 兜底**：仅要求「解析成功 + 目标是 `.exe`」（`lnk_target` 内含 `target.is_file()` 校验，apps.rs:736）；
3. **`.url` 兜底**：仅收已安装 Steam 游戏（`appmanifest_<appid>.acf` 校验）。

**垃圾入口是 `.lnk` 兜底层**：卸载器 / 更新器的快捷方式目标是真实存在的 exe，现有两条校验全拦不住；其标题与正式应用不同，标题去重（`seen`）也拦不住。此前真机反馈的 TAP adapter、以及本方案的卸载器类条目均走此路径混入。

## 2. 开源项目实际做法（源码已核实）

| 机制 | PowerToys Run (`Win32Program.cs` @ v0.101.2362.0) | Flow Launcher (`Win32.cs` @ dev) | ueli |
|---|---|---|---|
| .lnk 目标校验 | target 必须真实存在（`File.Exists(target) \|\| Directory.Exists(target)`，否则 `InvalidProgram`） | target 解析失败即无效 | —（走 PowerShell `Get-StartApps`） |
| 同 exe 去重 | `DeduplicatePrograms`（自定义相等比较器） | `ProgramsHasher`：按 `(ExecutablePath + Args)` 小写分组，组内优先开始菜单项 / 有 FileDescription 项，只取 1 个 | — |
| .url 协议白名单 | 正则 `^steam://(rungameid\|run\|open)/` 或 `^com.epicgames.launcher://apps/` 才有效 | builtin 协议表 = `steam://run/` + `steam://rungameid/`、`com.epicgames.launcher://apps/`、`http(s)://`（可配置扩展） | — |
| 名称黑名单 | **无** | **无**（issue [#2717](https://github.com/Flow-Launcher/Flow.Launcher/issues/2717) 仍在请求隐藏卸载器） | — |

**结论**：三家的核心防护是「目标存在性 + 同 exe 去重 + 协议白名单」；名称黑名单均未内置。但我们的问题恰是卸载器/更新器快捷方式——目标真实存在、前两条拦不住，故本方案在吸收其机制之上**额外增加名称黑名单**（本方案增量，用户诉求的直接解）。

来源：
- PowerToys `src/modules/launcher/Plugins/Microsoft.Plugin.Program/Programs/Win32Program.cs`
- Flow `Plugins/Flow.Launcher.Plugin.Program/Programs/Win32.cs` + `Settings.cs`（内置协议表）
- ueli `src/main/Extensions/ApplicationSearch/Windows/`（Get-StartApps 路线，无直接可借鉴的垃圾过滤，仅作对照）

## 3. 设计（4 项，全部落在 `builtins/apps.rs`）

### A — 目标 exe 文件名黑名单（最精准，误杀率最低）

新增纯函数 `is_junk_exe(target: &Path) -> bool`：对 `.lnk` 兜底层解析出的目标 exe 文件名匹配黑名单，命中即跳过。名单（大小写不敏感，覆盖主流安装器固定命名）：

- 卸载器：`unins*`（Inno `unins000.exe`）、`uninst*`、`uninstall*`、`*_uninst`、`un`
- 更新器：`update*`、`updater*`、`autoupdate*`
- 安装器残留：`setup*`、`install*`、`vcredist*`、`dxsetup`、`dotnetfx*`
- 崩溃 / 维护 / 辅助：`crashpad_handler*`、`crashreporter*`、`crashhandler*`、`maintenance*`（Qt MaintenanceTool）、`helper`

匹配规则 = **前缀 / 后缀 / 精确**三段式简单通配（`*_uninst` 为后缀例，`un`/`helper`/`dxsetup` 为精确例），不引入正则依赖。

**v1.2 修订（真机误杀 2026-09-12）**：`_update`/`_updater` 后缀规则**撤销**——真实应用主程序即有此命名（微信输入法主程序 `wetype_update.exe -showsetting`，探针实证），更新器由 `update*` 前缀 + 标题层兜底。

### B — 快捷方式标题关键词黑名单（双语，兜 A 的漏网）

新增纯函数 `is_junk_title(title: &str) -> bool`：对 `.lnk` 兜底层的显示名做**包含**匹配（大小写不敏感）。关键词为英文+中文**静态双表**（匹配数据非 UI 文案，不走 `tr()`）：

`uninstall`/`卸载`、`update`/`更新`、`setup`/`安装程序`、`help`/`帮助`、`readme`、`license`/`eula`/`许可`、`maintenance`/`维护`、`repair`/`修复`、`welcome`/`欢迎`、`crash`/`崩溃`。

**只作用于 `.lnk` 兜底层**；AppsFolder 枚举不套用——UWP/正式应用里确有「获取帮助」类真实应用，不碰 AppsFolder 可把误杀面收到最小。

**v1.1 修订（真机核验 2026-09-12 实证后扩展作用范围）**：真机探针发现垃圾项主要从 **AppsFolder 伪应用**混入——安装器把卸载器注册为 AppsFolder 项，parsing name 即显示名本身（如「卸载百度网盘」，无路径分隔符、非 AutoGenerated，原有过滤全部放行）；而其对应 `.lnk` 的标题在 AppsFolder 已 seen，`.lnk` 兜底层根本不会收录，**只过滤 `.lnk` 层拦不住**。故补 `appsfolder_title_allowed(parsing, title)`：

- **真 UWP 豁免**：packaged 应用 parsing name 必为 `PackageFamily!AppId` 形态（含 `!`），其名称可能合法含「帮助」等词（如系统应用「获取帮助」`Microsoft.GetHelp_8wekyb3d8bbwe!App`）——含 `!` 直接放行；
- **伪应用套黑名单**：快捷方式注册的项 parsing name 即显示名（无 `!`），套用 `is_junk_title`。

### C — 同 exe+参数 去重（吸收 Flow `ProgramsHasher`）

`.lnk` 兜底层新增去重键 `exe_dedup_key(target, args)` = **小写目标路径 + 小写启动参数**（对齐 Flow `ProgramsHasher` 的 `(ExecutablePath + Args)` 分组），多个快捷方式指向同一「exe+参数」只保留最先枚举到的一个。

**v1.2 修订（真机误杀 2026-09-12）**，两处：

1. **键必须含启动参数**——同 exe 靠参数分发的快捷方式不算重复：米哈游启动器三入口共用 `launcher.exe`，参数分别为 `--game=hk4e_cn`（原神）/ `--game=hkrpg_cn`（崩坏：星穹铁道）/ 空（启动器本体），按路径去重会吞掉两个真实游戏。实现 = `IShellLinkW` vtbl 补槽 10 `GetArguments`（IDL 槽序：GetPath=3、GetIDList=4、SetIDList=5、GetDescription=6、SetDescription=7、GetWorkingDirectory=8、SetWorkingDirectory=9、GetArguments=10、SetArguments=11——部分声明 vtbl 须按序占位 6 槽）。
2. **标题检查先于去重键消耗**——若同 exe 组内第一个快捷方式的标题已被 AppsFolder 占用（`seen` 命中），不得消耗去重名额，否则整组被误吞。

> 注：目标**存在性校验**已有——`lnk_target` 尾部 `target.is_file()` 等价 PowerToys 的 `File.Exists` 校验，死链已被拦，本项不重复实现。

### D — `.url` 协议白名单（吸收 PowerToys 正则 / Flow builtin 协议表）

现状：`.url` 接受**任意**协议（Steam 仅多做已安装校验），安装器生成的自定义协议推广/PWA 链接照单全收。新增 `url_protocol_allowed(url)` 白名单：`steam://run/`、`steam://rungameid/`、`steam://open/`、`com.epicgames.launcher://apps/`、`http://`、`https://` 前缀放行，其余不收录。Steam 已安装校验逻辑不变（仅对 `rungameid` 提 appid，Epic URL 不受影响照常收录）。

### 不做的

- **不读 exe 的 FileVersionInfo FileDescription**（Flow 用它优化去重展示；需新增版本资源 API，收益低）；
- 不做目录名过滤、不做 FileDescription 级语义判断；
- 不做用户自定义黑名单 UI（暂无设置通道，后续有需要再立项）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| B 关键词误杀真实应用（如标题含「更新/help」的正常软件） | ① 仅作用于 `.lnk` 兜底层，AppsFolder 优先收录的正式应用不受影响；② 名单保守（不含 `config`/`文档`/`tool` 等宽泛词）；③ 真机复验项专项抽查 |
| A 的 `un`/`helper` 精确匹配过宽 | `un` 与 `helper` 仅精确匹配文件名 stem（非前缀），误杀面极小 |
| 用户确实想启动某被过滤项 | 被过滤的都是安装器附属工具（卸载应走系统设置），属预期行为；如需恢复走「扩展管理」禁用 apps 扩展 |

## 5. 验证

- **单测**（纯函数）：`is_junk_exe` 正/反例（`unins000.exe` 命中、`noteins000.exe` 不命中等边界）、`is_junk_title` 双语正反例、`appsfolder_title_allowed` UWP 豁免规则（`!` 判别）、`exe_dedup_key` 大小写归一、`.url` 协议白名单正反例；
- **守卫**：`cargo fmt --check` / `cargo clippy --workspace --all-targets` / `cargo test --workspace` 全绿；
- **真机复验项**：① 列表无卸载/更新/崩溃报告类条目；② 无失效快捷方式残留；③ TAP 类不回归；④ Steam / Epic 游戏照常收录；⑤ **正常应用零误杀**（重点抽查标题含「更新」「帮助」的真实应用仍在列表）；
- **文档**：实施完成后按项目惯例在 `docs/implementation.md` §7 补批次记录。
